# HR POTOK

Веб-игра «Угадай большинство» для конференции. Участники открывают `/participant` на телефоне, ведущий управляет игрой в `/admin`, проектор показывает `/screen`.

## Открыть папку в VS Code

1. Установите Node.js LTS и Visual Studio Code, если их ещё нет.
2. Распакуйте или оставьте папку `hr-potok` в удобном месте на компьютере.
3. В VS Code нажмите **File → Open Folder…** (Файл → Открыть папку…) и выберите `hr-potok`.
4. Откройте **Terminal → New Terminal** (Терминал → Создать терминал). Убедитесь, что строка приглашения заканчивается на `hr-potok`.
5. Выполните `npm install` и дождитесь завершения загрузки.

## Подключить уже созданный Firebase Web App

1. В Firebase Console откройте проект **hr-potok**, затем шестерёнку → **Project settings** → **Your apps** → зарегистрированное Web-приложение.
2. Найдите блок **SDK setup and configuration** и выберите **Config**.
3. В VS Code создайте в корне проекта файл `.env.local` (рядом с `package.json`). Скопируйте туда строки из `.env.example` и заполните `API_KEY`, `AUTH_DOMAIN`, `APP_ID` и `MESSAGING_SENDER_ID` значениями из конфигурации Web App. `PROJECT_ID` и `DATABASE_URL` уже указаны.
4. Эти настройки Web App не являются паролем. Не вставляйте в файл пароль ведущего, закрытый ключ или файл сервисного аккаунта. `.env.local` исключён из Git.
5. Включите в Firebase Authentication способы **Email/Password** и **Anonymous**. Создайте email/пароль ведущего в консоли Firebase Authentication, если ещё не сделали этого.

## Локальный первый запуск

В терминале VS Code выполните `npm run dev`. Откройте адрес, который появится в терминале (обычно `http://localhost:5173`). На этом шаге можно проверить внешний вид и перейти по ссылкам «Участник», «Ведущий», «Экран».

Чтобы устройства в одной Wi‑Fi сети открыли локальную версию, используйте адрес компьютера в сети вместо `localhost`; для конференционного доступа из интернета сайт понадобится разместить на хостинге с HTTPS.

## Безопасность и порядок настройки

Согласованная структура данных:

- `/participants/{uid}` — имя участника, он может менять только свою запись.
- `/admins/{uid}` — признак ведущего; читать его может только соответствующий пользователь, менять через браузер нельзя.
- `/rounds/{roundId}` — закрытые серверные данные раунда, включая индивидуальные голоса и счётчики. Браузеры не имеют к ним доступа.
- `/game/current`, `/game/results/{roundId}` и `/game/leaderboard` — данные для экранов. Результаты отдельного раунда читаются только после его раскрытия.

Голосование выполняет callable Cloud Function. Она проверяет Firebase Authentication, статус раунда, наличие `optionId` среди вариантов текущего раунда и отсутствие предыдущего голоса этого UID; проверка и запись происходят транзакцией на сервере. Изменение фазы раунда также делается сервером. Firebase Admin SDK обходит Realtime Database Rules, поэтому правила всё равно запрещают прямые записи из браузера.

**Не публикуйте текущие более широкие правила поверх этой схемы.** Файл `database.rules.json` закрывает все записи по умолчанию, кроме личной записи имени участника, и запрещает браузеру читать `/rounds`. Перед использованием Rules и функции нужно проверить в Firebase Emulator Suite на проекте-копии или локальных эмуляторах. В этой рабочей среде Firebase Emulator Suite пока не запускалась, поэтому не считайте правила уже протестированными на вашей базе.

Чтобы локально проверить правила из файла: установите зависимости, затем выполните `npm run emulators`. Команда сохраняет локальные тестовые данные в `.emulator-data` при штатной остановке (Ctrl+C) и загружает их при следующем запуске. Для полного теста запросов к эмулятору понадобится зарегистрировать локального пользователя, добавить тестового ведущего в `/admins/{uid}` через Emulator UI и проверить: незалогиненный запрос отклонён; пользователь может сохранить только своё имя; участник не может менять игру, голоса или рейтинг; второй голос и неверный `optionId` отклоняются серверной функцией. Эмулятор — отдельная локальная база и не меняет опубликованные правила Firebase проекта.

Для использования реального проекта сначала опубликуйте проверенные `database.rules.json` через Firebase Console или `firebase deploy --only database`. Затем разверните Cloud Functions (`firebase deploy --only functions`). Для развертывания Cloud Functions может понадобиться тариф Firebase Blaze и настройка Google Cloud Billing. Только после этого callable функции будут доступны приложению в интернете.

### Добавить аккаунт ведущего

Войдите в `/admin` под email и паролем ведущего. На первом входе панель покажет его UID. В Firebase Console → Realtime Database добавьте узел `admins/{этот UID}` со значением boolean `true`. Вводить UID нужно только в консоль базы; не присылайте его в чат. Список ведущих могут менять владельцы проекта в Firebase Console; правила приложения это запрещают.

## Три экрана

- `/participant` — анонимный вход Firebase, игровое имя и голосование с телефона.
- `/admin` — отдельный вход email/паролем, запуск вопроса, раскрытие результатов и возврат в лобби.
- `/screen` — вопрос, итоговые полосы голосов и рейтинг для проектора.

## GitHub Pages

Для пошаговой публикации откройте [DEPLOY.md](./DEPLOY.md). Настроенный GitHub Actions собирает сайт для GitHub Pages, учитывает адрес проекта в подпапке и сохраняет прямые ссылки на `/participant`, `/admin` и `/screen`. GitHub Pages раздаёт только файлы сайта; синхронизацию и безопасную обработку голосов обеспечивает Firebase. Перед реальной конференцией подключите production Firebase, добавьте домен GitHub Pages в Authorized domains, разверните Cloud Functions и проверьте правила базы.
